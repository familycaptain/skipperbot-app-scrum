# Scrum App — Specification

## Overview

A companion to the platform's daily PM update. Every morning the Goals/PM
daily-standup runner scans goals, projects, tasks, and schedules and produces a
personalized check-in for each person. The **Scrum app** persists every item
that check-in raises so people can browse, filter, and respond to them from chat
or the desktop UI — and responding can roll the linked goal/task forward.

> **The daily items are GENERATED by the platform's Goals/PM runner, which
> writes them into this app's tables only when this app is installed.** Without
> the Scrum app installed there is nowhere to persist the items; with it, the PM
> runner calls `save_scrum_items_bulk(...)` once per day as part of its cycle.

## Data Model

### Table: `scrum_items` (schema `app_scrum`)

| Column             | Type          | Notes                                                  |
|--------------------|---------------|--------------------------------------------------------|
| id                 | TEXT PK       | `si-` prefix UUID                                      |
| report_date        | DATE NOT NULL | The calendar date this item was reported               |
| person             | TEXT NOT NULL | Canonical lowercase username (string ref → users.name) |
| item_type          | TEXT NOT NULL | `focus` · `done` · `blocked` · `finding` · `schedule`  |
| title              | TEXT NOT NULL | Short summary of the item                              |
| detail             | TEXT          | Full question / context from PM                        |
| source_entity_id   | TEXT          | Linked entity ID (task, project, goal, schedule) if any |
| source_entity_type | TEXT          | `task` · `project` · `goal` · `schedule`               |
| project_name       | TEXT          | Human-readable project name for display                |
| severity           | TEXT          | `critical` · `warning` · `info` (for findings)         |
| response           | TEXT          | User's reply (NULL until answered)                     |
| responded_at       | TIMESTAMPTZ   | When the user replied                                  |
| created_at         | TIMESTAMPTZ   | DEFAULT now()                                          |

**Indexes:**
- `(report_date)` — admin view across all users for a date
- `(person, report_date)` — primary per-person query pattern

When `source_entity_id` is set, a `linked_to` edge is recorded in `public.*`
via `data_layer.links.ensure_edge` (links are platform infra; no cross-schema FK).

### Item types

| Type       | Source                          | Title example                              |
|-----------|---------------------------------|--------------------------------------------|
| `focus`    | Standup Q2 — focus task         | "Working on: Deploy auth flow (t-abc)"     |
| `done`     | Standup Q1 — recent completions | "Completed: Fix login bug (t-def)"         |
| `blocked`  | Standup Q3 — blocked tasks      | "Blocked: API rate limit (t-ghi)"          |
| `finding`  | PM findings (rule + LLM)        | "Task 'Deploy' is overdue (due 2026-01-15)"|
| `schedule` | Schedule summary                | "Oil Change — F-150 (3d overdue)"          |

## Data layer (`data.py`, schema `app_scrum`)

- `save_scrum_item(...)` — insert one item (used by the freeform create route).
- `save_scrum_items_bulk(items)` — insert many in one transaction (used by the
  PM runner). Records `linked_to` edges for items with a source entity.
- `items_exist_for_date(report_date, person=None)` — idempotency guard so the PM
  runner doesn't double-write a day.
- `get_scrum_items(person=None, report_date=None, days=7, item_type=None)` — read
  with flexible filters.
- `respond_to_item(item_id, response)` — atomically save a response (no-op if the
  item already has one).

All reads/writes route through `app_platform.db` `*_in_schema` / `scoped_conn`
helpers so rows land in and read from `app_scrum`.

## Tools (chat)

| Tool                       | Description                                       |
|----------------------------|---------------------------------------------------|
| `get_pending_scrum_items`  | List today's unanswered items for a user          |
| `respond_to_scrum_item`    | Record a user response by `si-` ID; optionally roll the linked task forward via `task_action` (`mark_done` / `mark_in_progress` / `mark_blocked` / `""`) |

Registered under the `scrum` tool category with keywords: scrum, daily scrum,
standup, stand-up, daily standup, scrum item, scrum response, daily update, pm
update, check-in.

## REST API

Router mounted by the platform at `/api/apps/scrum`. Paths below are relative to
that mount.

| Method | Path                   | Description                                  |
|--------|------------------------|----------------------------------------------|
| GET    | `/`                    | List items. Params: `person`, `date` (YYYY-MM-DD), `days` (default 7, max 90), `item_type` |
| POST   | `/`                    | Create a freeform item (`item_type`, `title`, `person`, optional `response`) |
| POST   | `/{item_id}/respond`   | Save a response AND push it through the chat pipeline so the LLM can act on it |

The respond endpoint saves the response first, then fires a fire-and-forget chat
turn (loading the source entity's Definition of Done to drive task-closure
behavior). The chat-pipeline push imports platform internals (`chat`, `agent`,
`data_layer.goals`) lazily and is wrapped in try/except — if it fails, the saved
response is still returned.

## UI

**Singleton app**, registered as `scrum` (icon `ClipboardList`). Items grouped by
date (newest first), each date split into the three standup questions plus an
"Other" section for findings/schedule. Own, unanswered, today's items can be
replied to inline (textarea + send) or extended with freeform entries. Person
picker (defaults to the logged-in user) and a day-range picker drive the query.
The shell mounts the component — the app does not call `createRoot`.

## Platform dependencies

- **goals** — the Goals/PM daily-standup runner *generates* the scrum items
  (writing them here via `save_scrum_items_bulk`) and owns the tasks/projects a
  response can update (`apps.goals.store.update_item`). This app *persists and
  surfaces* them.
- **notifications** — delivery of the daily check-in.
- **db / links** — platform DB helpers and cross-entity links in `public.*`.
